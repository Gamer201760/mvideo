# Проверки приложения

## Описательные характеристики: 19.10.2026

Прошли 595 backend unit/integration тестов, Ruff, форматирование и mypy.
На полном тексте карточки очков проверены 11 поддержанных предложений:
камера, микрофоны, функции, аккумулятор, время работы, комплектация,
габариты и совместимость. Значения для теста восстановлены по цитатам:
исходный отвергнутый ответ модели в истории не хранится. Это проверка
корректных предложений, а не повтор исходного ответа внешней модели.

Контрпримеры проверяют чужой объект, отрицание, условность, приблизительность,
подмену режима использования, потерю «до», составные единицы, неверный тип
списка и неподтверждённый компонент. API и настоящая SQLite проверены при
полном заполнении, одном отказе и отказе по всем значениям новой категории.
Имена отклонённых полей остаются в схеме и пропусках после перезапуска;
отвергнутые значения в словарь не попадают. Модельный порт синтетический.

Frontend verify прошёл: 343 теста, 36 правил, типы, линтер и сборка.
На отдельном Compose-стенде без ключа прошли все 30 E2E, включая настоящий
перезапуск backend. Первый прогон дал 28/30: в тесте экспорта ожидалось
локальное значение до сохранения, запрос проверки добавленного поля
не передавал категорию. После исправления ожидания ответа сервера и контекста
карточки весь прогон повторён.
Сохранённая карточка на обновлённом локальном стенде проверена при
375/1440 px, RU/EN и обеих темах: восемь сочетаний без переполнения,
ошибок JavaScript и нарушений axe. Исправлен перенос длинных цитат.
База сохранена перед обновлением; 47 записей проверки, две записи истории
и десять категорий остались на месте. История не пересчитывалась.

На 193 ранее размеченных полях сохранились 93/93 корректных совпадения.
Повтор 120 сохранённых карточек с неизменными запросами: hybrid TP 327 → 328,
FP 109 → 110, FN 419 → 418; F1 55,33% → 55,41%, precision 75,00% → 74,89%.
Это повторно использованные диагностические данные. Новых вызовов внешней
модели нет; новая независимая проверка качества и калибровки не выполнялась.

[Отчёт и контрольные суммы](../reports/glasses-validation-v1.json).

## Проверка автопринятия: 19.10.2026

Прошли 528 backend unit/integration тестов, Ruff, форматирование и mypy.
Добавлены проверки точной биномиальной границы, неизвестных/пропущенных оценок,
знаменателя карточек, неверной категории, близких дублей, привязки рецензии к хешу
и запрета менять значения при сохранённых ID. Пакет слепой проверки повторно
воспроизведён побайтно. Исходники приложения и прежние рабочие стенды не менялись.

Два независимых субагента проверили 130 полных карточек и 284 переданных ответа.
[Контроль автопринятия](acceptance-validation.md) не подтвердил цель 95%:
91/120 полей и38/55 карточек подтверждены обоими. Рабочая эвристика не даёт
различия между допустимыми порогами 0,95 и 1. Это результат на агентской разметке
с локальным адаптером; внешняя модель и человеческая калибровка не проверены.

## Валидатор: итоговый прогон 19.10.2026

Прошли 511 backend unit/integration тестов, Ruff, форматирование и mypy.
Новые регрессии проверяют алиасы, порядок слов, двоеточия в значении,
точные цифровые идентификаторы и составные значения из положительных флагов.
Контрпримеры сохраняют отказы для чужого поля, отрицания, диапазона,
направления переходника, конфликтующих флагов, неизвестного компонента
и неподтверждённой единицы. Через API и настоящую SQLite проверены принятие
составного жанра и отказ при «Нет»/«неизвестно»; история совпадает после
перезапуска приложения. Модельный порт в этих тестах синтетический.

[Пересчёт сохранённых ответов](benchmark.md#исправления-валидатора-19102026):
6 из 18 разобранных ложных отказов устранены, все 93 прежних совпадения сохранены.
На 120 повторно использованных карточках F1 hybrid 54,00% → 55,33%, precision
75,30% → 75,00%. Gold/scorer прежние, новых внешних вызовов нет.
Frontend в этой задаче не менялся; предыдущий UI-прогон описан ниже.

## Общий каталог и ошибки шлюза: итоговый прогон 19.10.2026

Прошли 474 backend unit/integration теста, Ruff, проверка форматирования и mypy.
Новая категория доступна в `rules` и `hybrid` сразу и после перезапуска.
Добавление поля обновляет существующую категорию и уже использованный кэш правил.
Параллельные запросы к категориям с одинаковым названием поля и разными единицами
не смешивают профили. Старое обновление снимка не удаляет новые поля.

Проверены ошибки HTTP-адаптера через сценарий, API и настоящую SQLite:
таймаут, потеря соединения, перегрузка, недоступность, повреждённый ответ.
Неудачный запрос остаётся в истории как `failed`. При отказе группы успешные
карточки другой группы и их история сохраняются; неизвестный расход токенов
остаётся `null`. Повторные модельные вызовы автоматически не запускаются.

Frontend verify прошёл: 336 тестов, 36 правил, типы, линтер и сборка.
На отдельном Compose-стенде без ключа прошли все 27 E2E с настоящим перезапуском.
Затем настоящий HTTP-путь проверен на локальном тестовом сервере с синтетическими
ответами: 504 для таймаута, разные ошибки 503 для перегрузки и недоступности,
502 для повреждённого ответа, частичный успех пакета, отказ соединения после
остановки сервера, новая категория в обоих движках до и после перезапуска.
Это проверка транспорта и обработки сбоев, а не измерение внешней LLM.

Сообщение о перегрузке проверено в RU при 375 px в светлой теме и EN при 1440 px
в тёмной: без ошибок JavaScript, переполнения и нарушений axe. Оба состояния
просмотрены вручную. Внешняя модель не вызывалась.

## Ручное заполнение и отклонение: итоговый прогон 19.10.2026

Прошли 460 backend unit/integration тестов, Ruff, проверка форматирования и mypy.
На настоящей SQLite проверены добавление пропуска, отклонение и восстановление
в обоих движках, перезапуск, идемпотентность, изоляция карточек, миграция и откат.
Несуществующая цитата и постороннее поле отклоняются. При одновременных разных
добавлениях сохраняется одно решение; второе получает `409`. Завершающееся
извлечение не может перезаписать сохранённое отклонение.

Frontend verify прошёл: 336 тестов, 36 правил, типы, линтер и сборка.
На отдельном Compose-стенде без ключа шлюза прошли все 27 E2E, включая настоящий
перезапуск backend. После правки возврата фокуса отдельно повторно прошли оба
новых сценария. Добавление, отклонение, открытие истории, восстановление и экспорт
выполняются без повторного извлечения. При отключённом автоматическом принятии
значение с максимальным баллом можно подтвердить вручную.

Три состояния результата проверены при 375/1440 px, RU/EN и обеих темах:
24 состояния без ошибок JavaScript, горизонтального переполнения и нарушений axe.
Мобильная форма и результат на большом экране просмотрены вручную.

При проверке с `E2E_COMPOSE_PROJECT` используется `--workers=1`: тест перезапускает
общий backend и не должен прерывать запросы других браузерных тестов.
Внешняя модель не вызывалась. Этот прогон подтверждает работу ручного сценария;
он не измеряет качество извлечения или вероятностную калибровку порога.

## Пакеты, защита и порог: итоговый прогон 19.10.2026

После добавления пакетного API и политики принятия прошли 451 backend unit/integration
тест, Ruff, форматирование и mypy. Проверены настоящие миграции и SQLite,
сохранение решений при обновлении схемы, откат `auto_accepted` в `pending`,
границы порога, сохранение правки человека, лимиты, переставленные ответы,
частичный сбой групп и отсутствие неограниченного числа задач.

Frontend verify прошёл: 329 тестов, 36 правил, типы, линтер и сборка.
На отдельном снимке текущего runtime выполнен Compose-запуск с новым томом
без ключа шлюза. Все 25 E2E прошли, включая реальный перезапуск backend,
автоматическое принятие, ручную правку, восстановление, историю и экспорт.

Дополнительно результат просмотрен при 375/1440 px, RU/EN и обеих темах:
8 сочетаний без ошибок JavaScript, горизонтального переполнения и нарушений axe
после завершения анимаций. Через живой пакетный API 10 синтетических карточек
успешно обработаны за 3 обращения к локальному адаптеру.

[Профиль 100 синтетических карточек](scaling.md) показывает сокращение обращений
со 100 до 25. [Пересчёт сохранённых ответов](benchmark.md) проверяет текущую
валидацию на 120 реальных карточках без новых внешних вызовов. Эти измерения
имеют разные области применимости; качество LLM-батчей ими не измерено.

Автоматический прогон описан в [GitHub Actions](../.github/workflows/verify.yml).
Команды установки инструментов и зависимостей: [backend](../backend/README.md)
и [frontend](../frontend/README.md).

Браузерные тесты проверяют правку непосредственно в строке таблицы,
сохранение решения без нового извлечения, сохранение черновика и восстановление
результата без нового извлечения, синхронизацию решений между вкладками и явный
повтор прерванного запроса. История проверяется с пагинацией и открытием
сохранённого результата. Сценарий с двумя карточками одного названия проверяет,
что правка открытой из истории карточки не меняет решение для другого контекста.

Три сценария экспорта проверяют содержимое скачанного JSON после ручной правки,
экспорт старого результата с актуальными решениями и явный повтор после ошибки
сверки. Проверяются цитаты, контекст карточки и отсутствие нового извлечения.
Команда: `cd frontend && npm run e2e -- e2e/card-export.spec.ts`.
Для параллельных прогонов задавайте отдельный `--output`, чтобы не удалять
артефакты другого запуска.

Проверка строк параметров продавца закреплена тестами разбора и формы на RU/EN.
Отдельный браузерный прогон на новой тестовой SQLite: три теста ввода и валидации
прошли, включая `e2e/seller-validation.spec.ts`. Он проверяет причины ошибок,
сохранение строк после перезагрузки, раскрытие закрытого раздела, фокус и
отсутствие запросов извлечения до исправления. После исправления проверяется
состав отправленных параметров. Матрица ошибок 375/1440 px × RU/EN × две темы:
восемь сочетаний без нарушений axe, ошибок JavaScript и горизонтального переполнения;
скриншоты просмотрены. Внешняя модель не вызывалась.

Для проверки настоящего перезапуска backend запустите браузерные тесты с
`E2E_COMPOSE_PROJECT=имя_тестового_проекта` и `--workers=1`. Тест перезапустит
сервис `backend` указанного Compose-проекта, восстановит результат в браузере
и повторит извлечение с сохранённой правкой. Этот режим включён в CI.
Проверять нужно отдельный стенд без ключа шлюза.
