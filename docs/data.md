# Данные и EDA

Исходные файлы организаторов хранятся вне Git: `sku_desc.parquet`,
`query_clicks.parquet`, `skus.pkl`. Сохраните их в одной директории.
Выполните из `backend/`:

```bash
uv sync --locked --group data
uv run --group data python -m app.prepare_data \
  --raw /path/to/raw --out ../data/processed --threads 2
uv run --group data python -m analysis.execute \
  --raw /path/to/raw --processed ../data/processed
```

Команда подготовки создаёт карточки, gold, категории, клики, разбиение и
обязательные поля. `manifest.json` содержит SHA-256 всех входов и выходов,
настройки, количество строк и измеренный пик памяти. Существующий результат
не перезаписывается. При сбое сохраняется отдельная директория `.building`;
повтор следует запускать с новым путём вывода.

Gold — параметры `*_search` и каталожные бренд/модель. Они не попадают в
`seller_params`. Разбиение фиксировано seed=42; восемь категорий целиком
отложены. Обязательные поля и веса выводятся из каталога и трафика по эвристике;
их построение не заявляется независимым от test. Это принятая интерпретация
данных организаторов, а не подтверждённая ими ручная разметка.

Подготовка 19.10.2026: 189,2 с, два потока Arrow, пик RSS 4452,4 MiB
на локальной машине. Это отдельный офлайн-этап; его память превышает 4 GiB.
В production-образ зависимости анализа не устанавливаются.
Для ВМ данные подготавливаются заранее.

Восстановлены 1 481 914 карточек, 15 472 688 строк gold и 8297 определений
обязательных полей для 1107 категорий. Повторная подготовка входов бенчмарка
дала побайтовое совпадение `sample.jsonl`, `catalog.json`, `profiles.json`
и `weights.json` с завершённым измерением; вызовов модели не было.

## Выполненный анализ

[Notebook с результатами](../notebooks/eda.ipynb) и
[его исходник](../notebooks/eda.py) находятся в release.
Все шесть вычислительных ячеек выполнены заново без ошибок.
Перед расчётом проверяются контрольные суммы всех исходных и подготовленных файлов.
При отсутствии данных команда завершается с явной ошибкой, соседний checkout
не используется. Пути передаются ядру через переменные `EDA_*`.

Результаты: [сводный JSON](../reports/eda.json),
[длины текстов](images/eda/text-length.png),
[концентрация кликов](images/eda/click-concentration.png),
[значения gold в тексте](images/eda/gold-overlap.png).

Проверка на 20 000 train-карточек обнаруживает буквальное присутствие gold
в 58,41% обязательных пар. Это диагностическое пересечение строк, а не
семантический потолок recall: единицы, синонимы и подстроки требуют отдельной оценки.
Этот EDA описывает данные; качество извлечения измеряет [бенчмарк](benchmark.md).

## Проверка подготовки на небольших данных

```bash
uv run --group data pytest data_checks -q
```

Проверяются реальные parquet-файлы и CLI: отделение gold от входа, карточки
без описания и без каталога, контрольные суммы, отказ от перезаписи и
детерминированность повторной подготовки. Внешняя модель не используется.
