# Когда модель не вызывается

В основном режиме сначала проверяется результат правил. Вызов пропускается,
если выполнены все условия:

- score первой категории не ниже 0,35, отрыв от остальных — не меньше 0,10;
- правила заполнили все поля схемы, минимум два поля;
- нет повторяющихся полей, неоднозначных ответов и отклонённых цитат;
- каждое значение прошло доменные проверки и получило низкий уровень риска;
- в заголовке нет неразобранных слов, а остальные непустые строки содержат
  известные поля в формате «ключ: значение», целиком подтверждённые цитатами правил.

Свободное описание, неизвестное поле и дополнение к значению направляют карточку
к модели. Слова заголовка сверяются с категорией и найденными значениями.
Score поиска категории не является вероятностью. Значения по-прежнему поступают
в очередь проверки, а сохранённые решения человека применяются отдельно.
В смешанном batch модели передаются только неразобранные карточки.

Настройка `RULES_FIRST=true` включена по умолчанию и передаётся через Compose.
`RULES_FIRST=false` возвращает обращение к модели для каждой карточки.
После изменения настройки нужно пересоздать backend.

## Проверка 19 октября 2026 года

120 карточек, 746 эталонных слотов существующего бенчмарка. Текущая реализация
повторно обработала сохранённые ответы шлюза. Перед использованием каждого ответа
проверялось совпадение запроса, system и JSON-схемы. Новых внешних вызовов не было.

| Политика | Вызовы | F1 | Значения вне размеченных слотов |
|---|---:|---:|---:|
| Гибрид без пропуска вызовов | 120 | 54,10% | 877 |
| Только полнота схемы — предыдущий эксперимент | 115 | 54,86% | 850 |
| Полнота схемы и разобранный текст — текущая | 120 | 54,10% | 877 |

Предыдущая проверка показала экономию 5 вызовов — 4,17%. Разбор этих карточек
выявил потерю дополнительных характеристик из описания: среди них материал,
покрытие и срок службы батареи. Рост F1 по обязательным размеченным полям
не подтверждает сохранность всех полезных характеристик.

Текущая политика не пропустила ни одного вызова на этой выборке. Извлечения
совпали с обычным гибридом на всех 120 карточках. Общие p50 и p95 остались около
12,77 и 20,27 секунды. Это реконструкция: локальное время текущего прохода плюс
сохранённые длительности исходных вызовов шлюза. Новый сетевой и нагрузочный
прогон не проводился. Ускорение на реальных карточках пока не подтверждено.

Тест API отдельно подтверждает пропуск вызова на полностью структурированной
карточке. При добавлении неизвестного поля модель вызывается, и поле сохраняется
в результате. Эти тесты проверяют поведение, а не долю таких карточек в каталоге.

[Первоначальный отчёт](../reports/model-routing.json) сохранён как история.
[Повторная проверка](../reports/model-routing-followup.json) содержит хеши,
причины маршрутизации, изменения извлечений и срезы. Условия новой политики
записаны [отдельно](../reports/model-routing-followup-protocol.json).
Выборка использовалась ранее; это исследовательский пересчёт, а не независимый
тест. Значения вне эталонных слотов не размечены, их точность не измерена.

## Повторить без обращения к шлюзу

Нужен сохранённый bundle с ответами `hybrid` из [бенчмарка](benchmark.md).
Из `backend/`:

```bash
uv run --group benchmark python -m benchmarks.routing \
  --bundle ../data/benchmarks/release-v1 \
  --protocol ../reports/model-routing-followup-protocol.json \
  --output ../reports/model-routing-followup.json
```

Изменение входов или запросов останавливает пересчёт; новые ответы автоматически
не запрашиваются. Маршрутизация не получает gold: оно доступно только оценщику.
