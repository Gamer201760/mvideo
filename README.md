# Атрибуты товаров

Приложение получает текст карточки продавца и возвращает категорию, нормализованные
характеристики, точные цитаты и балл подтверждения. Обработка: regex → поиск категории
→ LLM при необходимости → валидация → SQLite. Без ключа работает локальный алгоритм.

## Запуск

Нужны Docker и Docker Compose v2. Исходные данные организаторов для запуска не нужны.

```bash
docker compose up --build -d --wait
```

Интерфейс: http://localhost:8080. API: http://localhost:8000/docs.
Миграции и загрузка синтетического демо-каталога выполняются автоматически.

Для подключения шлюза создайте `.env` на основе `.env.example` и задайте
`GATEWAY_URL`, `GATEWAY_API_KEY`, `GATEWAY_MODEL`.
Также поддерживаются `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`.
Ключ `OPENAI_API_KEY` используется только с явно заданным адресом шлюза.
При недоступности шлюза интерфейс явно показывает результат локальных правил.

## Пользовательский сценарий

Вставьте карточку или выберите пример, нажмите «Извлечь атрибуты».
Проверьте значения и цитаты. Изменение значения сохраняется по Enter или выходу
из поля; Escape отменяет ввод. Можно подтвердить, отклонить или восстановить
значение, добавить пропущенную характеристику с цитатой и скачать JSON.

Каждый запрос и его результат сохраняются в SQLite. История и ручные решения
доступны после перезапуска. Исправления применяются при повторной обработке
той же карточки. [Маршрут проверки](docs/for-jury.md).

## Данные и полное воспроизведение

Публичный репозиторий содержит код, документацию и тесты. Исходные данные
организаторов, реальные проверочные карточки и полные предсказания в него не входят.
Для полного расчёта получите `sku_desc.parquet`, `query_clicks.parquet` и `skus.pkl`
у организаторов или из закрытого репозитория команды. Создайте локальный архив:

```bash
python3 scripts/package_dataset.py --source /path/to/raw --output artifacts/source
```

После подготовки архива запустите данные, EDA, предсказания и проверку всей выгрузки:

```bash
bash scripts/reproduce_case.sh data/reproduced-v1
```

Команда создаёт новую папку и запускает инструменты с зафиксированными зависимостями
в Docker. Полный baseline формирует запись для каждого входного ID, включая пропуски
и неизвестные схемы. Это проверка исполнения правил, а не измерение точности LLM.
[Подробности и ресурсы](docs/reproducibility.md).

## Быстрая проверка API

Создайте синтетическую карточку и обработайте её через запущенный API без обращения к LLM:

```bash
cat > /tmp/admit-input.jsonl <<'JSONL'
{"id":"demo-1","title":"Смартфон Север S1 256 ГБ","description":"Цвет: черный. Диагональ: 6,5 дюйма. Аккумулятор: 5000 мАч."}
JSONL
python3 scripts/predict_dataset.py --base-url http://localhost:8080 \
  --input /tmp/admit-input.jsonl --output /tmp/admit-repeat/predictions.jsonl
```

Пример проверяет исполнение пайплайна и формат артефакта, а не качество на каталоге.
Выходной каталог должен быть новым; существующие результаты не перезаписываются.

## ВМ команды

В `~/project` выполните:

```bash
bash scripts/deploy_hackathon.sh
```

Скрипт читает `/opt/hackathon/ai.env`, использует модель
`ai-sage/GigaChat3.5-432B-A28B-Reasoning` и публикует интерфейс на `0.0.0.0:8000`.
Backend слушает только `127.0.0.1:8001`. Другую модель можно передать через `OPENAI_MODEL`.
[Демо](https://tochka-sborki-2026-team-025.hub.gigaschool.ru) требует входа в GIGASCHOOL Hub.
Сдача кода: `git push origin main`.

## Проверки и ограничения

[Команды тестирования](docs/verification.md) · [Архитектура](docs/architecture.md) ·
[API](docs/api.md) · [Пакеты и порог](docs/scaling.md) · [Документация](docs/README.md).

Балл подтверждения — эвристика, а не вероятность правильности.
`AUTO_ACCEPT=false` включает ручную проверку всех новых значений.
Демо-каталог ограничен; полный EDA и обработка всего исходного набора запускаются
командой воспроизведения выше.
Качество текущей внешней модели на независимой выборке не измерено.

Остановка с сохранением SQLite: `docker compose down`.
