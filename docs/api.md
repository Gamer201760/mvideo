# Результат извлечения

`POST /api/v1/extract` возвращает заполненные поля в `values`, дополнительные
в `extra_values`, незаполненные поля категории в `missing`.

В режиме `hybrid` поле `rejections` содержит причины отказа после проверки
значения по цитате. Каждый элемент включает `attribute`, код `reason` и исходную
цитату `evidence`. Отвергнутое значение не передаётся как заполненное и не
добавляется в очередь подтверждения. Если для поля найдено другое подтверждение
или сохранено исправление человека, оно выводится в заполненных полях.

| Код | Причина |
|---|---|
| `invalid_evidence` | Цитата отсутствует в карточке |
| `field_mismatch` | Цитата описывает другое поле |
| `field_unconfirmed` | Не установлена связь с нужным полем |
| `field_type_mismatch` | Значение не соответствует типу поля |
| `conditional_support` | Условную поддержку нельзя передать безусловным значением |
| `object_context` | Характеристика другого товара или упаковки |
| `value_unconfirmed` | Значение не подтверждено текстом |
| `negation`, `negation_unconfirmed` | Не совпадает отрицание |
| `number_unconfirmed` | Не совпадают число, знак или единица |
| `unit_mismatch` | Несовместимые единицы |
| `range_lost`, `range_mismatch` | Потерян или изменён диапазон |
| `conflicting_values`, `model_conflict` | Противоречащие значения |

Поле `rejections` по умолчанию пустое. Остальные поля ответа сохраняют свой формат.
Полный контракт доступен в `/openapi.json` работающего backend.

Ошибки одиночного извлечения возвращаются в общем формате `{code, message}`:

| HTTP | Код | Причина |
|---|---|---|
| 504 | `model_timeout` | Истёк таймаут вызова или ожидания слота |
| 503 | `model_rate_limited` | Модельный сервис вернул HTTP 429 |
| 503 | `model_unavailable` | Нет соединения с сервисом или он вернул неуспешный HTTP-ответ |
| 502 | `invalid_model_output` | Повреждён ответ HTTP, JSON, структура результата или ответ обрезан |
| 503 | `model_capacity` | Заполнена локальная очередь |
| 422 | `model_input_too_large` | Карточка со схемами не помещается в лимит запроса |
| 503 | `model_failure` | Другой известный отказ модельного порта |

Ограничение провайдера возвращается как 503: оно относится к доступности общего
сервиса, а не к персональной квоте пользователя стенда. Сообщения не содержат
тела ответа провайдера, адреса запроса или ключа. Автоматических повторных вызовов
нет. Сбой одиночного извлечения сохраняется в истории со статусом `failed`.
У пакета HTTP-ответ остаётся 200 при частичном успехе: код ошибки записывается
в соответствующий элемент, успешные результаты и их история сохраняются.

В `hybrid` поле `confidence` содержит операционный балл подтверждения,
`threshold` — порог принятия, `auto_accept_enabled` — состояние политики.
`acceptance` различает `automatic`, `manual` и `review`. Балл не является
откалиброванной вероятностью. Автоматически принятые записи имеют статус
хранения `auto_accepted`; запрос очереди с `status=pending` их не возвращает.
Ручная правка такой записи разрешена без `override`; повторная правка решения
человека по-прежнему требует сверки `expected_value`.

`POST /api/v1/extract/batch` обрабатывает до 100 карточек с уникальными `id`.
Ответ содержит результат или ошибку каждого ID, его `run_id` и сводку числа
обращений/токенов. Полный формат и ограничения: [пакеты и порог](scaling.md).

История доступна через `GET /api/v1/runs?offset=0&limit=20` (максимум 100 записей).
Ответ содержит `items` и общее число `total`; новые запросы идут первыми.
Статусы: `running`, `completed`, `failed`, `interrupted`.
`GET /api/v1/runs/{run_id}` возвращает `input`, `result` и `status`.
У незавершённых и неудачных запросов `result` равен `null`.
Открытие записи не запускает модель. История общая для локального стенда;
авторизации и пользовательских сессий в нём нет.

`POST /api/v1/review/{item_id}` принимает `action: accept | correct | reject` и для правки `value`.
Подтверждение сохраняет текущее значение. Ручная повторная правка принятого значения
требует `override: true` и `expected_value`, равного последнему подтверждённому значению.
При несовпадении сервер возвращает `409` без изменения решения. Повтор одного и того же
успешного запроса идемпотентен. Подтверждение или правка и обучающий алиас сохраняются одной транзакцией.
Подтверждение и правка в таблице обновляют состояние карточки без повторного извлечения.

Отклонение сохраняет `status: rejected`, `resolved_value: null` и время решения.
Оно не создаёт обучающий алиас. Значение исключается из результата при открытии истории,
экспорте и повторном извлечении той же карточки. Для отклонения ранее принятого человеком
значения нужны `override: true` и его текущее `expected_value`; для автоматического принятия
достаточно `action: reject`. Восстановление отклонённого значения выполняется через
`action: correct`, `override: true`, `expected_value: null` и новое `value`.

`POST /api/v1/review/add` добавляет пропущенное поле обработанной карточки:

```json
{
  "card": {
    "engine": "hybrid",
    "title": "Смартфон",
    "description": "Оттенок корпуса лазурный",
    "category_id": 761
  },
  "attribute": "Цвет",
  "value": "лазурный",
  "evidence": "Оттенок корпуса лазурный"
}
```

`card` имеет формат `ExtractRequest`; для автоматически определённой категории передаётся
её ID из результата. Сервер проверяет наличие сохранённой карточки, принадлежность поля
категории, непустое значение и точное вхождение цитаты в полный текст карточки.
Ответ имеет формат `ReviewItemSchema`, статус `corrected`, источник `review`.
Результат помечается `acceptance: manual`; уверенность модели новому значению не назначается.
Человек отвечает за смысловую связь значения с цитатой: проверка вхождения не доказывает её.

Неизвестная карточка возвращает `404`; отсутствующая цитата, постороннее поле и пустое
значение возвращают `422`. Попытка добавить уже заполненное поле или заменить сохранённое
решение без явной правки возвращает `409`. Одинаковое повторное добавление идемпотентно.
Две одновременные разные правки не перезаписывают друг друга. Решения привязаны к полному
содержимому карточки и категории, включая атрибуты продавца; другая карточка их не наследует.
