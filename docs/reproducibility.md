# Проверка отдельного снимка release

Снимок собирается из текущих файлов, включая ещё не закоммиченные изменения:

```bash
python3 scripts/export_release.py --output /path/to/release-copy
python3 scripts/export_release.py --verify /path/to/release-copy
```

Экспорт содержит код, lock-файлы, миграции, синтетический seed, документацию,
EDA и агрегированные отчёты. `.git`, `.env`, сырые данные, локальные базы,
кеши и установленные зависимости исключаются. Каждый файл проверяется
по SHA-256 из `release-manifest.json`. Существующий путь не перезаписывается.

Из новой директории выполните обычную команду:

```bash
docker compose up --build -d
```

По умолчанию интерфейс работает на http://localhost:8080, API — на
http://localhost:8000. Без ключа выполняется локальный алгоритм.
Для отдельной проверки рядом с работающим стендом:

```bash
COMPOSE_PROJECT_NAME=mvideo-review FRONTEND_PORT=8081 BACKEND_PORT=8001 \
  GATEWAY_API_KEY= docker compose up --build -d
```

Проверка 19.10.2026 выполнена на отдельном снимке из 500 файлов, изолированном
Compose-проекте и новом томе SQLite. Сборка, миграции, seed и проверки готовности
backend/frontend прошли. Использовались локальные правила и синтетические карточки;
внешняя модель не вызывалась.

Все 21 браузерный тест на этом снимке прошли. Маршрут проверяет извлечение с цитатами, пропуски, исправление,
повтор, историю, экспорт результата и доступность. Один сценарий действительно
перезапускает backend и проверяет сохранность решения. Результаты каждого прогона
нужно сохранять в отдельную директорию Playwright через `--output`, чтобы
параллельные проверки не удаляли trace друг друга.

Проверка снимка подтверждает переносимость его содержимого. Она не является
проверкой будущего опубликованного Git-коммита. Коммит и публикация выполняются
после согласования версии; затем проверку нужно привязать к его SHA.

## Если запуск не удался

| Симптом | Что проверить |
|---|---|
| Docker daemon недоступен | Запустить Docker и проверить `docker info` |
| Порт занят | Задать свободные `FRONTEND_PORT` и `BACKEND_PORT` |
| Ошибка миграции или seed | Посмотреть `docker compose logs migrate seed` |
| API не готов | Посмотреть `docker compose ps` и `docker compose logs backend` |
| Шлюз недоступен | Проверить адрес и ключ; для локальной проверки запустить отдельный проект с пустым ключом |
| CLI не находит dbmate | Установить dbmate 2.36.0 или задать `DBMATE_BIN`; запуск через Compose использует готовый образ |
| EDA не находит данные | Выполнить [подготовку исходных файлов](data.md) и передать явные пути |

`docker compose down` останавливает проект с сохранением тома SQLite.
`/api/v1/ready` показывает стартовую конфигурацию; доступность внешней модели
этот endpoint не проверяет. Автоматического переключения на правила при сбое
настроенного шлюза сейчас нет.
