# Backend

Асинхронный FastAPI: regex, поиск категории, извлечение через шлюз и проверка цитат.
Категории, очередь проверки и исправления сохраняются в SQLite.

Приложение с миграциями и начальными данными запускается из корня:

```bash
docker compose up --build -d
```

API: http://localhost:8000/docs. Готовность: `/api/v1/ready`.

## Проверки

Нужны Python 3.12+, uv и dbmate 2.36.0. Команды выполняются в `backend/`.

```bash
uv sync --locked
uv run ruff check .
uv run mypy .
uv run pytest tests/unit
uv run pytest tests/integration
```

Интеграционные тесты создают временную базу, применяют миграции и загружают
синтетические примеры. Если dbmate отсутствует в PATH, задайте `DBMATE_BIN` — путь
к исполняемому файлу.

Политика пропуска модельного вызова включена через `RULES_FIRST=true`.
Условия пропуска: [маршрутизация](../docs/model-routing.md).

`POST /api/v1/extract/batch` обрабатывает до 100 карточек и возвращает результат
каждого ID, историю и сводку обращений. По умолчанию модель получает группы
до четырёх карточек, одновременно исполняются до двух обращений.
`ACCEPTANCE_THRESHOLD=0.95` задаёт порог для подтверждённых низкорисковых значений;
`AUTO_ACCEPT=false` включает ручную проверку всех новых значений.
[Контракт и настройки](../docs/scaling.md).

[Небольшой проверочный набор API](../docs/benchmark.md)
воспроизводится стандартным Python-скриптом. Полная выгрузка всех карточек
использует потоковый CLI с производственными функциями извлечения и валидации;
[команда полного воспроизведения](../docs/reproducibility.md).
Обычные тесты не вызывают внешнюю модель.

[Подготовка организаторских данных и EDA](../docs/data.md) используют отдельную
группу `data`; в production-образ она не устанавливается.
