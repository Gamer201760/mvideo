# Воспроизводимый файл предсказаний

## Полный набор

Полная выгрузка, сохранённая в закрытом репозитории команды, обрабатывает все
1 481 914 карточек подготовленного набора в исходном порядке. Сжатые JSONL-части
содержат входной ID, исходную и выбранную категории, значения с цитатами,
пропущенные поля или явный статус отсутствия данных/схемы. Контрольные суммы
источников, частей и потока ID записаны в манифесте. Проверка всех строк
описана в [инструкции воспроизведения](reproducibility.md). В публичную копию
данные и готовая выгрузка не входят; их можно вычислить после получения исходников.

Используются локальные правила и производственные функции подготовки текста,
поиска категории, нормализации, валидации цитат и принятия. Отдельные вызовы API
и записи SQLite для полутора миллионов строк заменены потоковой записью артефакта.
Это выгрузка исполнения, без вызовов LLM и без оценки независимой точности.

Первую запись собственного запуска можно прочитать штатным Python 3.10+:

```bash
python3 - <<'PY'
import gzip
import json
with gzip.open("data/reproduced-v1/predictions/predictions-00000.jsonl.gz", "rt", encoding="utf-8") as stream:
    print(json.dumps(json.loads(next(stream)), ensure_ascii=False, indent=2))
PY
```

## Быстрая проверка API

В закрытом репозитории есть небольшой набор из 12 реальных карточек организаторов:
шесть смартфонов и шесть ноутбуков. Он выбран детерминированно и предназначен
для проверки цепочки «вход → основной API → сохранённый результат».

| Артефакт | Назначение |
|---|---|
| `examples/validation/cards.jsonl` | Входные ID и текстовые поля карточек |
| `examples/validation/provenance.json` | Источник, способ отбора и контрольные суммы |
| `artifacts/validation/predictions.jsonl` | Результат или ошибка каждой входной карточки |
| `artifacts/validation/manifest.json` | Режим исполнения, количество записей и SHA-256 |

## Повторение

Запустите приложение по [README](../README.md). Для публичной копии используйте
[синтетический вход](../README.md#быстрая-проверка-api) или собственный JSONL.
Если проверочный набор получен отдельно, из корня репозитория:

```bash
python3 scripts/predict_dataset.py --base-url http://localhost:8080 \
  --input examples/validation/cards.jsonl --output /tmp/admit-repeat/predictions.jsonl
```

По умолчанию используется `engine=rules`, поэтому вызова LLM не происходит.
Обработка идёт через `/api/v1/extract`: результат одновременно сохраняется
в SQLite приложения и в выходной JSONL-файл. При ошибке конкретной карточки
её ID и ошибка остаются в файле. Рядом создаётся `manifest.json` с контрольными суммами и состоянием обработки.
Существующие выходной файл, манифест или незавершённый checkpoint не перезаписываются.

Сравнивайте ID, значения, цитаты, пропуски и ошибки. Времена и идентификаторы
записей истории зависят от запуска. Ручные решения в существующей SQLite
могут изменить результат; для повторения исходного состояния используйте
новый Compose-проект и новый том по [инструкции](reproducibility.md).

## Область применимости

Тексты входов реальные; встроенные схемы и словари демонстрационного каталога
ограничены. Проверочный набор не содержит весь исходный датасет, не служит
независимой оценкой качества и не подтверждает калибровку балла.
Файл предсказаний получен правилами, а не внешней моделью.

Для обработки другого набора передайте собственный JSONL того же формата.
Полный EDA и подготовка исходных файлов описаны [отдельно](data.md).
