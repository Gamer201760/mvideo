# Проверка автопринятия

19.10.2026 фиксированное правило с порогом 0,95 **не прошло проверку** относительно
двух независимых агентских рецензий. [Машиночитаемый отчёт](../reports/acceptance-study-v1.json).
Проверялся зафиксированный hybrid-сценарий с локальным адаптером `local_rules` и импортированным
каталогом из 1107 категорий. Это не замер внешней модели или встроенного демо-каталога.

После этого измерения валидатор изменён: [проверки описательных характеристик](verification.md#описательные-характеристики-19102026).
Отчёт сохраняет результат прежней версии и не подтверждает качество обновлённой.
Для новой версии нужен отдельный контрольный набор.

## Результат контрольной части

| Показатель | Результат |
| --- | ---: |
| Входные карточки | 100 |
| Карточки хотя бы с одним автопринятым полем | 55 |
| Автопринятые поля | 120 |
| Поля с подтверждённой категорией и значением у обоих рецензентов | 91 / 120 — 75,83% |
| Карточки с подтверждённой категорией и всеми автопринятыми полями | 38 / 55 — 69,09% |
| Нижняя односторонняя точная биномиальная граница 95% по карточкам | 57,32% |
| Охват карточек автопринятием | 55,00% |
| Автопринятые поля / все поддержанные ответы | 120 / 1030 — 11,65% |

Пять карточек с 14 автопринятыми полями не получили согласованного подтверждения
категории. На других 12 карточках не подтверждены 15 значений. Среди ошибок —
усечение диапазона до числа, неправильное поле, отрицание и неполный идентификатор.
Разногласия по трём значениям и одной категории сохранены как неподтверждение.

Числа показывают согласованность с агентской разметкой, а не человеческую оценку
точности. Даже при 55/55 подтверждениях нижняя граница составила бы только 94,70%.
Набор после просмотра результатов не расширялся. Отдельные 30 карточек `tune`
также сохранены: 30/40 подтверждённых полей и 12/19 полностью подтверждённых
непустых карточек; изменения правил по ним в этой работе не выполнялись.

## Почему повышение порога не решает проблему

В проверенной конфигурации `EvidenceRiskModel` не подключён. Эвристика даёт всем
ответам, допустимым для автопринятия, балл 1,00. Политика дополнительно требует
низкого риска и только положительных оснований. Поэтому пороги 0,95 и 1,00
принимают один и тот же набор. Этот балл не является вероятностью правильности.

Рабочая политика в этой задаче не менялась. Для режима только ручной проверки
уже предусмотрено `AUTO_ACCEPT=false`. Новый scorer и исправления правил требуют
нового отдельного контрольного набора; текущая часть `confirm` после такой
доработки станет данными разработки.

## Набор и проверка

Зафиксированы 130 карточек: 30 `tune`, 100 `confirm`. Отбор по SHA256(seed:sku_id)
выполнен до извлечения и рецензий, без каталожного gold. Исключены 13 384 SKU из
315 сохранённых исторических файлов и предыдущего benchmark. Проверены 434 092
обучающих и исторических карточки из processed-источника. Близость определена
как Jaccard множеств нормализованных словных триграмм ≥0,8. Из 431 доступного
кандидата в исходном пуле исключены 258; осталось 173, первые 130 зафиксированы.
Взаимные близкие дубли тоже исключены. Это лексическая проверка; семантические
дубли и неизвестные внешние эксперименты ею не исключаются.

Каждая карточка проходит текущий сценарий без переданной истинной категории,
сохранённой обратной связи и обученного риск-модуля. Зафиксированы 1354 поддержанных
ответа. Для рецензий выбраны все 160 автопринятых ответов обеих частей и до одного
контрольного ответа на карточку, всего 284. Сокращение разметки не меняет знаменатель
охвата: в нём остаются все поддержанные ответы.

Два субагента независимо прочитали полные 130 входов, предсказанный путь категории
и итоговые нормализованные значения с единицами и цитатами. Они не видели баллы,
статусы принятия, разбиение, gold и чужую рецензию. Каждый результат связан с хешем
входного пакета. Совпавшие ID с изменённым текстом, категорией или значением не
позволяют пересчитать отчёт. Пропущенная оценка и неизвестный ответ не удаляются
из знаменателя. Поля одного товара объединяются в один исход карточки для основного
расчёта; ошибки агентской разметки и зависимость карточек интервалом не учитываются.

Биномиальная нижняя граница вычисляется обращением хвоста распределения при
alpha=0,05. [Метод точных биномиальных границ](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbino.htm)
описан NIST. В частности, для всех успешных карточек граница равна `0.05 ** (1/n)`;
59/59 дают границу выше 95%, 58/58 — ниже. Это проверено регрессиями.

## Повторение

Нужны приватные processed-данные, bundle `release-v1`, список путей исторических
артефактов и две независимые рецензии. Каталожные метки или одна автоматическая
проверка цитат не заменяют рецензии. Команды из `backend/`; выходные пути должны
быть новыми:

```bash
uv run --group benchmark python -m benchmarks.acceptance_sample \
  --data ../../data/processed --bundle ../data/benchmarks/release-v1 \
  --history-list ../.local/acceptance-study-v1/history-paths.txt \
  --output ../.local/acceptance-repeat/bundle
uv run --group benchmark python -m benchmarks.acceptance_run \
  --bundle ../.local/acceptance-repeat/bundle \
  --catalog ../data/benchmarks/release-v1/catalog.json \
  --output ../.local/acceptance-repeat/run
```

`run/review-chunk-*.jsonl` содержат полные слепые входы. Каждый рецензент создаёт
отдельный JSONL со всеми карточками и переданными `answer_id`:

```json
{"card_id":"C0001","reviewer":"A","input_sha256":"SHA256 run/review-subset.jsonl","full_input_reviewed":true,"category_correct":true,"category_reason":"Основание по полному входу","answers":[{"answer_id":"C0001:A1","correct":true,"reason":"Основание для поля и итогового значения"}]}
```

`category_correct` и `correct` допускают `true`, `false`, `null`. Для второго
рецензента требуется другой идентификатор; решения не копируются. После проверки:

```bash
uv run --group benchmark python -m benchmarks.acceptance_score \
  --bundle ../.local/acceptance-repeat/bundle \
  --predictions ../.local/acceptance-repeat/run \
  --reviews ../.local/acceptance-repeat/review-a.jsonl \
  --reviews ../.local/acceptance-repeat/review-b.jsonl \
  --report ../.local/acceptance-repeat/report.json
```

Новый запуск на том же наборе повторяет уже использованные данные и не создаёт
новую независимую проверку. При изменении runtime сохранённый `confirm` блокируется
для подтверждения новой версии. Новых внешних вызовов продуктовой модели в этом
исследовании нет; агентские рецензии имеют отдельное происхождение.
